# 固定种子聚类合并评分：设计依据与验证

## 设计说明

| 项目 | 说明 |
| --- | --- |
| 选择的考点 | [论文第 3.1 节末尾](https://arxiv.org/html/2603.28480v1#S3.SS1)区分原始与去偏空间；[第 3.4 节公式（12）—（14）](https://arxiv.org/html/2603.28480v1#S3.SS4)将图内与跨图相似度结合。作者固定提交 `0c165a10cf52ab91f335883d06260de86854adbe` 的 [`_seed_and_aggregate:331–364`](https://github.com/visinf/INSID3/blob/0c165a10cf52ab91f335883d06260de86854adbe/models/insid3.py#L331-L364)及 [`compute_cluster_prototypes:28–44`](https://github.com/visinf/INSID3/blob/0c165a10cf52ab91f335883d06260de86854adbe/utils/clustering.py#L28-L44)确定具体统计和权重。 |
| 题目思路 | 在种子已知、patch 已归一化的条件下，实现一个评分函数，返回聚类分数和整簇掩码。接口把上游处理全部移出题目，使验证只依赖这一个叶节点。 |
| 难点假设 | 模型可能把“去偏有利于匹配”推广为所有比较都使用去偏特征；或者抽取一个通用“归一化均值原型”辅助函数，并将它同时用于图内和跨图分数；也可能将候选掩码仅当作簇筛选条件，遗漏覆盖率或种子覆盖率特例。这些是待验证的错误假设，不是已经观察到的 GPT-5.5 行为。 |
| 最小验证例子 | 使用下文四个 patch、两个聚类、一个固定种子。正确分数为 `[1, 17/(20√13)]`，阈值为 `0.24` 时仅保留种子簇的两个 patch。 |
| 预期错误结果 | 图内相似度也在去偏空间计算时，非种子分数为 `0.25`；误用归一化的去偏均值原型，或遗漏非种子覆盖率时，分数为 `17/(10√13) ≈ 0.471495`。三种错误均会错误合并非种子簇。若遗漏种子权重特例，种子分数为 `0.5`。 |
| 如何判断 | `test_bonus_task.py` 同时断言数学分数和最终布尔掩码。除核心四 patch 例子外，还用不对称簇、不同覆盖率和种子分数不为 1 的输入区分错误均值、最大值和权重计算；用负分及零均值检查明确的接口边界。测试不读取实现源码，也不以函数是否能调用作为正确性标准。 |

## 论文与代码的对应边界

图内分数采用原始特征的聚类均值，均值再归一化；这个归一化来自作者 `compute_cluster_prototypes`。跨图分数采用去偏 patch 与参考原型的逐 patch 内积，在每个聚类内取均值，**不把去偏聚类均值再次归一化**。虽然对均值作内积等价于对内积求均值，归一化均值会改变其长度，因此不再等价。

作者代码还将分数乘以“簇内候选 patch 数 / 簇的全部 patch 数”，并将种子的该权重设为 `1`。这些覆盖率细节并未出现在论文公式（13）的简单乘积中。论文公式（14）使用 `≥` 并显式并入种子；作者代码对所有簇统一使用 `>`，没有无条件并入种子的步骤。题面明确采用指定代码行为，避免把论文和代码差异作为隐瞒条件的陷阱。

## 最小例子的手算

设位置方向为第一通道 `e₁`，参考去偏原型为 `p=(0,1,0)`。四个 patch 位于 `(2,2)` 网格，按行优先顺序排列：

| patch | 标签 | 是否候选 | 原始特征 | 去偏特征 |
| --- | --- | --- | --- | --- |
| 0 | 0 | 是 | `(3/5, 4/5, 0)` | `(0, 1, 0)` |
| 1 | 0 | 否 | `(3/5, 4/5, 0)` | `(0, 1, 0)` |
| 2 | 1 | 是 | `(3/5, 2/5, 2√3/5)` | `(0, 1/2, √3/2)` |
| 3 | 1 | 否 | `(3/5, 2/5, −2√3/5)` | `(0, 1/2, −√3/2)` |

所有非零特征均为单位向量。去偏特征确实可由原始特征去除第一通道并重新归一化得到，并非任意拼接的两套数据。固定种子为标签 `0`。

种子原始原型为 `(3/5,4/5,0)`。标签 `1` 的原始均值为 `(3/5,2/5,0)`，归一化后为 `(3/√13,2/√13,0)`，与种子的图内相似度为 `17/(5√13)`。该簇两个去偏 patch 与参考原型的内积均为 `1/2`，跨图分数因此为 `1/2`。候选覆盖率为 `1/2`。

非种子最终分数为：

```text
(17 / (5√13)) × (1/2) × (1/2)
= 17 / (20√13)
≈ 0.23574758339572238
```

种子跨图与图内相似度均为 `1`，覆盖率虽然也是 `1/2`，但按代码将其权重设为 `1`，所以种子最终分数为 `1`。阈值 `0.24` 的输出为：

```text
[[True,  True],
 [False, False]]
```

若错误地在去偏空间计算图内原型，两簇的归一化原型均为 `(0,1,0)`，非种子图内相似度变为 `1`，分数变为 `0.25`。若错误地先归一化去偏聚类均值再计算跨图分数，则跨图分数从 `1/2` 变为 `1`。两种错误都丢失了原方法中的信息，输出却仍表现为合理的相似度和完整掩码。

## 不对称与边界补充例子

四 patch 核心例子中的簇大小相同、覆盖率都为 `1/2`，同簇 patch 的跨图分数也相同。单靠它无法区分“最大值与均值”“候选 patch 均值与全簇均值”“全图覆盖率与逐簇覆盖率”，也无法证明种子只覆盖权重、没有直接把最终分数设为 1。新增如下小型输入：

| 例子 | 输入 | 手算期望及判别作用 |
| --- | --- | --- |
| 不对称簇 | `(1,6,2)` 网格，原始与去偏特征均为 `[(3/5,4/5),(3/5,4/5),(1,0),(3/5,4/5),(3/5,−4/5),(−1,0)]`；参考原型 `(1,0)`；标签 `[2,2,0,0,0,1]`；候选 `[1,0,1,1,0,0]`；种子 `2`；阈值 `0.25`。 | 标签 0 的跨图均值为 `11/15`，图内分数为 `3/5`，覆盖率为 `2/3`，最终分数为 `22/75`；标签 1 没有候选，分数为 0；种子最终分数为 `3/5`。按标签顺序的分数为 `[22/75,0,3/5]`，掩码前五个位置为真。 |
| 保留负分 | 特征均为 `[(1,0),(3/5,4/5)]`；参考原型 `(0,−1)`；标签 `[0,1]`；候选均为真；种子 `0`；阈值 `−0.25`。 | 分数为 `[0,−12/25]`，掩码 `[True,False]`。将负分裁剪到零会改变输出。 |
| 零均值种子 | 特征均为 `[(1,0),(−1,0),(0,1)]`；参考原型 `(0,1)`；标签 `[0,0,1]`；候选 `[1,0,1]`；种子 `0`；阈值 `0`。 | 种子原始均值为零，所有图内分数均为零，因此分数为 `[0,0]`，掩码全假；直接除以零范数会产生非法值。 |

这些输入验证题面给定的固定种子叶节点接口；不重新运行或假定上游候选定位、聚类和种子选择。负阈值及零均值是题面明确允许的接口边界，不作为完整分割流程的推荐设置。

## 验证范围与公平性

共 7 项测试，涵盖核心手算、两种阈值的整簇选择、标签互换、严格阈值、不对称聚类、负分及零均值。手算期望是测试的判定依据，不调用第一题函数或参考实现来生成期望值。

浮点断言采用 `rtol=1e-6, atol=1e-7`。原先 `1e-12` 的容差会误拒仅因输出精度不同的正确 float32 答案，且没有提高对 `0.23575` 与 `0.25` 等方法差异的识别能力。加载器采用标准包导入，支持合法的延迟注解、`dataclass` 和包内相对导入，不以代码组织方式制造难度。

后续只有把实际 GPT-5.5 提交放入题面规定的文件，并在统一环境运行这些测试，才能判断模型是否犯错。即使测试失败，也应结合断言和源码检查具体原因；失败本身不能证明一定采用了某一种预设错误逻辑。
